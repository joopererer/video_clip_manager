# 语义检索质量评估集（v1.1.0 发布准备）

本目录是**可复现的检索质量评估集**。离线契约部分由 `test/semantic_retrieval_quality_test.dart` 自动执行；真实语料部分需要在本机安装好 EmbeddingGemma 2 模型与 sidecar 后人工记录。

## 为什么分两部分

- **离线契约（已自动化）**：把已知单位向量直接写入帧池，验证阈值、排序、最佳命中帧映射、中文查询预处理与结果分布形状。不需要模型、不需要媒体、确定可复现。
- **真实语料（待人工）**：需要真实视频、真实帧嵌入和真实查询向量。本阶段开发环境没有 sidecar 二进制与 542MB 模型，因此无法在 CI 式环境中跑真实检索。

## 离线契约结论（自动断言，v1.1.0）

| 审计项 | 结论 | 依据 |
| --- | --- | --- |
| 返回 Top-K 还是全部超过阈值 | 全部超过阈值，**没有 Top-K 截断** | 12 个同等相似度片段全部返回 |
| minScore 实际值 | `performSemanticSearch(minScore: 0.28)` 默认 0.28，调用处不覆盖 | `lib/data/app_state.dart` |
| 分数范围 | 余弦相似度，理论 `[-1, 1]`；实测分布集中在 0.28–0.95 | 契约测试 |
| 是否存在凑数量 | 不会补齐数量，但**阈值是唯一过滤条件**，0.30 这种低分会被返回 | 边界用例 0.30 被返回、0.10 被过滤 |
| 片段相似度 ↔ 最佳命中帧 | 同一帧同时产出分数与时间戳（`computeMaxSim`），映射一致 | 广/窄区间用例 |
| 排序是否按实际相似度 | `AppState.getFilteredClips` 按分数降序；**但 ClipsTab 之前用默认「最新添加」重排，语义排序被覆盖** | 见下方"本阶段修复" |
| 中文查询预处理 | 仅 `trim` 后加 `search_query: ` 前缀送模型，不做分词/清洗，原文不被改写 | 契约测试 |

### 本阶段修复的最小缺陷

1. **语义排序被 UI 排序覆盖**：`ClipsTab` 默认按 `dateAddedDesc` 重排，导致"最相关的排第一"失效。现新增「相关度最高」排序项，并在存在语义分数时作为默认排序。
2. **HIT 时间戳会被写进用户数据库**：`VideoClip.toJson` 包含 `hitTimestampMs`，而卡片上的评分/收藏操作会把带 HIT 的副本回写，重启后仍显示旧 HIT。现在 `addClip` / `updateClip` / `updateClipSilently` 在落库前剥离 HIT，`getFilteredClips` 对没有当前命中的片段也剥离历史 HIT。**Schema 未改动。**

### 未改动（按需求保留）

- `minScore` 默认值 0.28 未调整。
- 未删除低分结果、未加 Top-K。
- 未修改模型、分词、前缀、下载链路。

## 真实语料评估表

`queries.csv` 是记录模板。填写方式：

1. 在真实数据库上搜索每个查询词，按 Enter 触发 AI 语义检索。
2. 逐条记录：结果顺序、界面显示的 `Score`、HIT 时间码、该结果是否真的相关（1/0）、以及"最佳命中帧截图是否确实匹配查询语义"。
3. 记录当时使用的模型目录与片段总数（顶部上下文）。

字段说明：

| 字段 | 含义 |
| --- | --- |
| `query` | 搜索词 |
| `query_kind` | 查询类型（物体 / 动作 / 场景 / 复合） |
| `rank` | 结果在「相关度最高」排序下的位次 |
| `clip` | 片段名 |
| `score` | 界面显示的 Score（三位小数，直接抄录，不得估算） |
| `hit_tc` | HIT 时间码 |
| `relevant` | 人工判定 1=相关，0=不相关 |
| `frame_ok` | HIT 帧画面是否真的对应该语义，1/0 |
| `note` | 备注 |

用户已观察到的现象（待用本表量化）：

- `自行车`：6 个结果里约 1 个相关 → 重点记录第 2–6 名的 score 分布，判断是否集中在 0.28–0.40。
- `短裤`：多数结果相关，HIT 帧准确 → 作为"表现良好"的对照组。

## 检索模式方案（建议，本阶段不实现）

| 模式 | 行为 | 适用 |
| --- | --- | --- |
| 严格 | `minScore ≈ 0.45` + Top-K 10 + 相对阈值（最高分 × 0.85） | 只要高置信结果 |
| 平衡（当前默认行为的改进版） | `minScore ≈ 0.32` + 相对阈值 + Top-K 30 | 日常使用 |
| 宽松 | `minScore ≈ 0.22` + 无 Top-K | 探索、找相似镜头 |

实现时应把阈值做成用户可见设置并持久化，同时保留"显示实际分数"，避免出现"看起来精确但其实是截断值"的数字。
